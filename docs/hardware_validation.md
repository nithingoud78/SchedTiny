# SchedTiny Hardware Validation (Phase 12)

## Overview

Phase 12 transforms SchedTiny from a simulation project into a real embedded systems research platform. It introduces a modular Platform Abstraction Layer (HAL) that allows the framework to run on actual STM32 hardware while keeping the core scheduler logic platform-independent.

## Hardware Architecture

The initial hardware validation targets the **STM32 Nucleo H743ZI2** development board.

- **MCU**: STM32H743ZI (Cortex-M7, 400 MHz)
- **Timer Measurement**: Cortex-M DWT (Data Watchpoint and Trace) Cycle Counter.
- **GPIO Indication**: User LEDs (LD1, LD2, LD3 on GPIOB).

## Platform Abstraction Layer

To ensure the core scheduler remains generic and testable on the host, hardware-specific features are completely isolated behind generic interfaces in `firmware/platform/stm32/`.

### Modules
- `platform_init`: Responsible for invoking `HAL_Init()` and orchestrating subsystem initialization.
- `platform_timer`: Provides microsecond-level timing capabilities using the internal DWT cycle counter, which is significantly more accurate than SysTick for measuring sub-microsecond overheads.
- `platform_clock`: Configures the System PLL (running at up to 400 MHz on H7).
- `platform_gpio`: Abstraction for mapping logical `PLATFORM_LED_1..3` to physical STM32 pins for visual debugging.

## Measurement Methodology

### DWT Cycle Counter
Instead of relying on the coarse 1ms SysTick for overhead measurement, the platform uses the DWT (Data Watchpoint and Trace) register `DWT->CYCCNT`.

- **Precision**: 1 CPU cycle (e.g., 2.5 nanoseconds at 400 MHz).
- **Measurement**: `platform_timestamp_us()` divides the cycle count by the core frequency in MHz to return a standardized microsecond value.
- **Overhead Tracking**: The scheduler invocation inside `sched_benchmark_run` captures the timestamp before and after `sched_dispatcher_dispatch` and submits the differential to `sched_stats_record_latency()`.

## Benchmark Integration Summary

The existing benchmarking framework (`sched_benchmark.c`) has been seamlessly integrated with the new platform layer.
- `printf` relies on a retargeted `_write` implementation in `platform_init.c` to output data over the ITM (Instruction Trace Macrocell) or UART.
- The same JSON and CSV structures generated by the host simulator are successfully exported by the STM32 over serial.
- The python ingestion scripts remain fully compatible since the output formatting matches exactly.

## Future Work Enabled by this Phase

1. **Physical Power Measurement**: Connecting Joulescopes to the Nucleo board to measure the exact energy cost of context switching vs. active inference.
2. **True ISR Preemption**: Injecting hardware interrupts (via UART, EXTI, or Timer events) and measuring preemption latencies using the DWT.
3. **Hardware-in-the-Loop (HIL) CI**: Executing the SchedTiny validation suite automatically on a physical board rack for continuous hardware validation.
